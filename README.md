# Практическая работа: небольшая библиотека (Java)

## Структура проекта

```text
src/
├── library/
│   ├── Book.java
│   └── LibraryDesk.java
└── app/
    └── Main.java
README.md
```

## Таблица доступа

Обозначения: **Да** — обращение разрешено; **Нет** — компилятор запрещает.

| Что проверяем | Внутри Book | Внутри LibraryDesk | Внутри Main |
|---|---:|---:|---:|
| Чтение поля `author` (`public`) | Да | Да | Да |
| Чтение поля `title` (`private`) | Да | Нет | Нет |
| Чтение поля `inventoryNumber` (без модификатора) | Да | Да | Нет |
| Чтение поля `shelf` (`protected`) | Да | Да | Нет |
| Вызов `printInfo()` (`public`) | Да | Да | Да |
| Вызов `canBorrow()` (`private`) | Да | Нет | Нет |
| Вызов `assignInventoryNumber(...)` (без модификатора) | Да | Да | Нет |
| Вызов `moveToShelf(...)` (`protected`) | Да | Да | Нет |
| `new Book("Название", "Автор")` (`public`) | Да | Да | Да |
| `new Book("Название", "Автор", "B-010")` (без модификатора) | Да | Да | Нет |
| `new Book("Название")` (`protected`) | Да | Да | Нет |
| `new Book()` (`private`) | Да | Нет | Нет |

## Объяснение

- `public` доступен из любого класса и пакета.
- `private` доступен только внутри класса `Book`.
- Модификатор без слова (`package-private`) разрешает доступ всем классам пакета `library`, но не классу из `app`.
- `protected` доступен внутри своего пакета. Из другого пакета он доступен только наследникам при соблюдении правил Java; `Main` не является наследником `Book`.
- `LibraryDesk` может вызвать конструктор с тремя параметрами и метод `moveToShelf(...)`, потому что оба класса находятся в пакете `library`.
- `Main` может вызвать `prepareBook(...)`, поскольку этот метод объявлен `public`. Сам конструктор с тремя параметрами и `moveToShelf(...)` из `app` недоступны.

## Проверка компиляции и запуск

Из корня проекта:

```bash
cd src
javac library/Book.java library/LibraryDesk.java app/Main.java
java app.Main
```

## Примеры запрещенных обращений

Ошибочные строки оставлены комментариями в `Main.java`, `LibraryDesk.java` и `Book.java` не содержит обращений снаружи к закрытым членам. Чтобы увидеть ошибку компиляции, временно уберите `//` у соответствующей строки, затем снова закомментируйте ее.

В `Main` запрещены обращения к `title`, `inventoryNumber`, `shelf`, `canBorrow()`, `assignInventoryNumber(...)`, `moveToShelf(...)`, а также вызовы трех непубличных конструкторов. Причины указаны рядом с примерами в комментариях.

В `LibraryDesk` запрещены обращения к `title`, `canBorrow()` и приватному конструктору без параметров. Остальные непубличные члены доступны, так как класс находится в том же пакете `library`.

## Основной сценарий

Создаются четыре объекта `Book`. Повторная выдача уже выданного экземпляра и повторный возврат свободного экземпляра возвращают `false`. Два экземпляра «Хоббита» имеют независимое состояние. Переменная `sameBook` содержит ссылку на тот же объект, что и `first`, поэтому изменение через одну ссылку видно через другую. Счетчик в конце остается равным `4`.
